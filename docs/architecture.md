# First-slice architecture

Investigated 2026-09-29 against EmDash main `54209bc9bd0b48e12bdefa8ac971da01ced7990f` (core 1.0.1) and Medusa main `037232847319a12b83f597cce06e24371f96e81f` (2.21.2). The foundation is checked against installed published host packages and a clean consumer of the locally packed plugin.

1. **Native mode is required for the full slice.** The plugin CLI/registry contract cannot ship custom Portable Text definitions plus site Astro components. Native `PluginDescriptor` → `createPlugin` → `definePlugin` supports these and a React `adminEntry`. Network requests and encrypted settings alone do not require native mode.
2. **Only Store API reads belong in the plugin.** Products list/retrieve and regions use `x-publishable-api-key`. Admin API is used exclusively by a disposable local seed tool to create sample data. No Admin credential is a plugin setting.
3. **Settings:** backend URL, publishable key, optional default region and sales channel. The key is declared `secret` for write-only admin display and AES-GCM storage using EmDash's `EMDASH_ENCRYPTION_KEY`, even though Medusa considers it public. Runtime reads use `ctx.settings`.
4. **Browser boundary:** a publishable key, public backend URL, region/channel IDs may reach a storefront. This slice keeps its configured key server-side. Admin credentials must never reach browser code. Admin search receives normalized Store product data only.
5. **Direct HTTP:** the tiny catalog client uses a supplied fetch function; production supplies `ctx.http.fetch`. This preserves EmDash's network authority and adds timeouts, redirect rejection, response limits, validation and safe diagnostics. No Medusa SDK is needed for three GET operations. Reconsider its browser cart/session support when carts are in scope.
6. **Commerce context:** the publishable key restricts accessible sales channels. An optional channel narrows it further; it cannot grant access. Region is an explicit default and can be selected from Store regions in native admin. Do not guess the first region for prices. Channel IDs cannot be discovered via a Store sales-channel-list endpoint and must come from Medusa Admin. Visitor region/cart context is future work.
7. **SSR via a public plugin route:** the Astro block uses EmDash's existing `getPublicPluginApiRouteHandler(Astro.locals)` to dispatch a public single-product route in-process. Settings and HTTP remain inside plugin context. No loopback fetch to the CMS, no raw runtime access, no credential endpoint. The route returns only normalized public product data plus a safe configured href, or null. Public failures expose no internal diagnostics; plugin-context logs record a stable error code/product ID, with normal missing products at debug level. A site must SSR for live prices; prerendering freezes commerce until rebuild.
8. **References:** Portable Text stores `_type`, `_key`, `productId`, `display`, and `showPrice` only. It does not store titles, thumbnails, prices, inventory or a product snapshot. IDs are validated; missing/deleted products produce a calm unavailable state.
9. **Future carts:** Medusa owns cart ID, region, sales channel, line items, variants and totals. A small browser island or existing storefront manages cart context and calls Store APIs; checkout delegates to a Medusa-backed storefront. EmDash must not become a commerce admin or duplicate its records.
10. **Known friction:** `optionsRoute` POSTs `{}` once and expects `{ items: [{ id, name }] }`; it passes no search, pagination or selected-ID context. The native admin can separately search Medusa with `q`, but the block's stock select is bounded to a small catalog. A public Store route needs deployment rate limiting before production. Pricing requires `region_id` and `+variants.calculated_price`; amounts are major currency units in v2 (format directly, never divide by 100). Product-card minimum prices are catalog estimates, not tax/shipping/payment totals.

## Supported networking model

The supported deployment contract is a publicly reachable HTTPS Medusa Store API whose exact origin is approved in site plugin configuration. Private-network and localhost endpoints are not supported in this foundation: EmDash `createHttpAccess` applies SSRF checks to native and sandboxed plugins, rejects private/loopback addresses even in `allowedHosts`, and has no supported private-host opt-in. Supporting private backends is deferred to upstream EmDash network-policy support. The production implementation retains `ctx.http.fetch`; there is no unrestricted/global-fetch fallback, proxy workaround or host-policy patch.

Local development/testing alone uses a temporary HTTPS tunnel to an **allowlisted, read-only Store gateway**, never Medusa Admin/auth. Its origin is pinned in site options with an exact hostname passed to EmDash. It exercises the supported production transport, while adding an external dependency only to browser tests. Unit, installed-tarball consumer and real Medusa HTTP integration checks need no tunnel or hosted Medusa service.

## Product links and diagnostics

`productUrlTemplate?: string | null` is normalized identically by the descriptor and runtime. Default/null disables links. A root-relative path or absolute HTTPS URL can contain exactly one `:handle` token in the path; query/fragment and other templating are intentionally unsupported. The encoded handle cannot change the fixed authority. The public route computes href server-side; Astro validates it again and renders a link only when present. Portable Text still stores references/presentation choices only.

Public lookup failures and missing products share `{ ok: true, product: null }` and the existing calm renderer fallback. EmDash `ctx.log.warn` records stable failure code and validated product ID; `ctx.log.debug` records normal `NOT_FOUND`. Logs never receive upstream bodies, sensitive headers, credentials or raw exception messages. Missing settings/encryption report `CONFIGURATION`; transport, timeout, response validation and key/context rejection retain distinct codes. The renderer cannot access plugin-context logs if the public dispatcher is missing or throws before route execution; that boundary remains a documented limitation.

The first-100 picker and separate native admin remote search remain unchanged. A supported EmDash extension/upstream search/pagination contract belongs in a future PR; no editor workaround or catalog replication is included.
